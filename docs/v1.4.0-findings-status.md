# v1.4.0 Adversarial Finding Status

This catalogue tracks the 32 findings from the v1.3.0 adversarial review against
the v1.4.0 implementation. `Fixed` means code and focused regression coverage
exist. `Qualification` means the code change exists but the release candidate
must still pass the listed live-cluster or backend test before GA.

| ID | Status | v1.4.0 disposition |
| --- | --- | --- |
| C-1 | Fixed | Snapshot idempotency no longer depends on the unsafe process-local map; durable state and deterministic backend names are used. |
| H-1 | Fixed | TLS verification defaults on, custom CA files are supported, and insecure mode warns. |
| H-2 | Qualification | Freeze records are durable, startup recovery and a maximum-window watchdog thaw abandoned targets; kill-during-freeze E2E remains a GA gate. |
| H-3 | Fixed | NFS directory creation holds the canonical backing-mount reference for the full operation. |
| H-4 | Fixed | Publish/unpublish use canonical backing-share keys and balanced references. |
| H-5 | Fixed | HTTP 400 without a running create task returns an error instead of false success. |
| H-6 | Fixed | gRPC logging redacts CSI secret fields. |
| M-1 | Fixed | Expansion is serialized, compares configured quota, and never shrinks a share. |
| M-2 | Qualification | File-backed creation formats a same-directory temporary file and atomically renames it; crash-injection E2E remains. |
| M-3 | Fixed | In-flight mount identity includes target, source, and options, preserving portal fallback. |
| M-4 | Fixed | Auth retry rebuilds request bodies, closes discarded responses, and serializes login. |
| M-5 | Fixed | Stage/unstage are serialized and marker-read failures fail closed. |
| M-6 | Fixed | Mount probes use mountinfo and do not strand timed-out goroutines. |
| M-7 | Fixed | Existence and snapshot-list failures propagate as retryable operation failures. |
| M-8 | Fixed | Empty filesystem type follows the default NFS capacity path. |
| M-9 | Fixed | Capability validation derives the volume type from its canonical ID. |
| M-10 | Qualification | XFS grows through its mount path, ext4 through its loop device, and raw files without filesystem operations; live online/offline matrix remains. |
| M-11 | Fixed | NFS node expansion returns a response and volume capability is required and validated. |
| L-1 | Fixed | Cache TTL preserves configured durations and handles disabled expiration explicitly. |
| L-2 | Fixed | Library request errors return to the caller instead of terminating the process. |
| L-3 | Fixed | Empty snapshot responses are checked before indexing. |
| L-4 | Fixed | Per-key locks are reference counted and removed after their last waiter/holder. |
| L-5 | Fixed | ListVolumes returns canonical IDs with deterministic pagination. |
| L-6 | Qualification | Snapshot IDs and state are backend-authoritative and durable; backend timestamp/readiness qualification remains. |
| L-7 | Fixed | The shared staging design is explicit, persistent, and documented. |
| L-8 | Fixed | Readonly NFS publication includes the `ro` mount option. |
| L-9 | Fixed | The driver no longer advertises `RPC_UNKNOWN`. |
| L-10 | Fixed | Environment validation accepts only supported CSI 1.x operation. |
| L-11 | Fixed | Backend 5xx responses are errors, not file-not-found results. |
| L-12 | Fixed | Staging moved from `/tmp` to `/var/lib/hammerspace/csi-staging`. |
| L-13 | Fixed | Partial node failures clean up the resolved loop device and mount state. |
| L-14 | Qualification | Controller staging is on a durable host path and reconciled; restart/failover E2E remains. |

## GA qualification still required

The remaining `Qualification` rows cannot be truthfully closed by unit tests or
static manifest validation alone. They require the release image, a running
Kubernetes cluster, destructive disposable PVCs, and an approved Hammerspace
test tenant. The required runs are defined in `release-checklist.md` and the E2E
matrix in `v1.4.0-action-plan.md`.
